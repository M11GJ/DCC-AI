## Native tool-call recovery repair

The Pipe now instructs the model to use native API tool_calls rather than XML/DSML. On tool-enabled requests, it holds completion chunks until the provider finishes, detects unfenced terminal invocation blocks even after prose or across chunk boundaries, and regenerates a violating response once through the same provider and tool definitions. XML is never interpreted as an executable call. Regenerated calls must name an exposed function with JSON-object arguments; repeated protocol violations fail explicitly. Fenced code examples and tool_choice=none are excluded. Native calls preserve provider IDs and exact reasoning_content; retry token usage is added to original usage. Tool-enabled streaming output is buffered, including reasoning, to prevent publishing abandoned reasoning/text; this delays first visible generation. Requests without tools preserve their prior stream behavior.
